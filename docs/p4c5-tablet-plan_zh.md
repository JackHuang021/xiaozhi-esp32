# P4C5 平板化产品规划（Launcher + 多 App）

- **适用范围**：p4c5 板卡（ESP32-P4 + ESP32-C5），分支 `p4c5_dev`
- **撰写日期**：2026-09-04
- **产品形态**：把现有的"语音聊天助手"升级为**类平板设备** —— 开机进入**桌面（图标启动器）**，点击图标进入对应 App，可返回桌面。
- **配套文档**：总路线图 [p4c5-feature-roadmap_zh.md](p4c5-feature-roadmap_zh.md)（含既有方向 A–D 细节）；USB 细节 [p4c5-usb-plan_zh.md](p4c5-usb-plan_zh.md)。

> 本文是**规划**。带 ① 的段落是需要板主拍板/确认的决策点；凡标"待确认硬件"的项要先定再开发。

## 1. 产品愿景与范围

**一句话**：一台放在桌上的"AI 小平板"——平时是**桌面**（时钟/天气/图标），点图标分别进：**语音助手、MP3、照相机、文件管理、USB 电脑副屏**；顶栏常驻时间/电量/网络，任何界面可回桌面。

它建立在**同一块 p4c5 硬件**上（不改板），本质是把闲置的 6.2" 屏空间和 P4 算力做成一套小型的"平板 OS + 应用生态"。语音不再是全部，而是**五分之一**。

**明确不做（v1）**：全局语音唤醒（见 D2）、后台多任务、安装第三方 App、横竖屏动态旋转、OS 级原生副屏驱动（见 App-E 说明）。

## 2. 系统架构

### 2.1 分层

```
┌─────────────────────────────────────────────┐
│  系统层：WiFi(C5)/网络 · OTA · 时间/NTP · 设置 · PMU/背光/电池 │  一直运行
├─────────────────────────────────────────────┤
│  壳 Shell：AppManager(生命周期/栈) · Launcher(桌面) · 状态栏(顶层) │
│           · 手势(回桌面) · 通知/系统弹窗覆盖层            │
├─────────────────────────────────────────────┤
│  App 层：语音助手 / MP3 / 照相机 / 文件管理 / USB副屏    │  前台 1 个
├─────────────────────────────────────────────┤
│  基础设施：LVGL(esp_lvgl_adapter) · AudioFocus · VFS(存储) · 输入(触摸/USB键盘) │
└─────────────────────────────────────────────┘
```

### 2.2 Shell 与 App 生命周期（新模块）

- 新增一个轻量 **App 接口 + AppManager**，每屏是 LVGL 的一个 screen（LVGL 9.5 多 screen 原生支持）：
  - `App::OnCreate(lv_obj_t* parent)` / `OnResume()` / `OnPause()` / `OnDestroy()`；
  - `AppManager::Launch(app_id)` 切换前台 screen；**返回/Home 手势**回到 Launcher；记录简单返回栈。
- **Launcher 是默认 App**（不是普通 App，固定在栈底）。
- 建议 v1 代码放 `main/boards/p4c5/`（如 `p4c5/apps/`），稳定后再讨论上提到共享层，减少与上游冲突。
- 现有聊天 UI 直接变成"语音助手 App"的视图；桌面与其互为兄弟 screen，用 screen 切换而非塞进同一容器。

### 2.3 状态栏与通知（全局，常驻所有 App 之上）

- 复用/改造现有顶栏：时间、WiFi、电量、音量、静音 → 放到 **`lv_layer_top()`**（LVGL 顶层，任何 App 之上），各 App 只画内容区 1280×(452−状态栏高)。
- 系统通知（低电量、USB 插入等）复用 `ShowNotification` 覆盖层。
- 助手进入对话时若需要全屏沉浸（聊天在 452 高的窄条里很紧张），可让助手 App 自己再隐藏顶栏 → 回桌面恢复（记录为 UI 决策点，先保持顶栏常驻）。

### 2.4 音频焦点（AudioFocusManager）

- 全板只有一个 ES8389 输出；v1 单前台已经天然互斥，但需要**一个显式的焦点仲裁**，原因：系统音（低电量/提示音）要能在任何 App 上响，且 MP3/助手在切屏时正确释放 I2S。
- 策略：`request(zone)`，zone = SYSTEM > ASSISTANT > MEDIA；新申请者抢占旧持有者并回调 `onFocusLoss`（旧持有者保存进度/暂停）。MP3 被抢占应能续播。

### 2.5 存储布局（统一约定）

| 路径 | 用途 |
|---|---|
| `/sdcard/Music` | MP3/音乐 |
| `/sdcard/DCIM` | 相机照片/录像 |
| `/sdcard/Pictures` | 图片（文件管理看图、壁纸） |
| `/sdcard/Downloads` | 导入导出 |
| `/sdcard/Backup` | 设置/日志备份 |
| `/usb`（若实现 U 盘） | U 盘挂载点 |

### 2.6 输入

- 触摸（现状）。
- USB 键盘（D-H1，做时生效）路由到**当前前台 App 的焦点控件**（文本输入框），作为全局输入服务提供。

## 3. 启动器 Launcher（桌面）

**功能**：图标主屏 + 待机仪表。
- 横屏 1280×452：顶栏之下放一排 **App 图标**（5 个起点，后续可加"设置/关于"），点按开屏；图标下方名称。
- 其余区域是**待机时钟**（大字号 时:分 + 日期/星期/天气占位），即原规划 B1 的内容，但它是桌面的一个 widget 而非聊天 Home。
- 交互：点图标 → App；顶部/角落"回桌面"热区或**左滑手势** → 回 Launcher（需在 App 屏上注册手势，注意与 App 内部滑动冲突的取舍，先用"返回箭头"兜底）。

**技术路径**：新 Launcher screen，图标用 LVGL image/字体图标（assets 已有 material_symbols 与字体体系）；桌面时钟刷新沿用 `MAIN_EVENT_CLOCK_TICK`→`UpdateStatusBar` 的机制，但桌面自绘大时钟。

**验收**：开机 5s 内见桌面；点击 5 个图标能进对应 App 且能回到桌面。

## 4. 五个 App 详规

### App-1 语音助手（复用现有能力，改造"何时运行"）

- **UX**：点图标进入 → 呈现现有聊天屏（对话气泡/表情/状态栏）；支持唤醒词 + 免提持续对话（沿用现有 device_state_machine）；顶栏显示"退出助手"按钮/手势。
- **改造核心**：把现在"开机即全局语音待机"改成"**进入 App 才启动音频/唤醒引擎，退出即停止**"（D2）。系统层（网络/OTA/时间）保持运行。
  - 现有引擎入口：`main/application.cc` 的状态机（`kDeviceStateIdle/Listening/...`，见 `main/device_state.h`）；把它从"开机自动运行"改为"App Resume 启动 / Pause 停止"，UI 回调（`SetChatMessage` 等）在助手屏激活时才指向它。
- **可选增强**：界面上加"拍一张让我看看"按钮（接 A0，等摄像头硬件）；会话中调用系统其它 App 的动作可暂缓（多 App 联动后续再加）。
- **工作量 M（重构为主）**；**优先级 P0（壳子的第一个验证对象）**。
- **验收**：桌面进助手→正常对话；按退出→回桌面、麦克风停止、再进可继续新会话。

### App-2 MP3 音乐播放器

- **UX**：全屏播放器：曲目列表（从 `/sdcard/Music` 扫目录，解析 ID3 标题/艺术家）、正在播放（封面占位/歌名/进度条/上一首-播放-下一首/音量）、播放列表循环/随机。
- **技术路径（新增量最大的一块音频）**：
  - **MP3 解码**：项目现无解码器（现有链路是 opus/ogg 语音，见 `main/audio/`）。引入轻量 **Helix MP3**（ESP-ADF 同款）或验证 `espressif/esp_audio_codec` 是否覆盖；v1 覆盖 **MP3 + WAV**。
  - **输出**：解码 PCM → 喂现有 ES8389 输出。注意 ES8389 现被语音链路按 16k 配置；媒体播放需**切采样率(44.1k)并在退出时还原**，且必须走 AudioFocus（见 2.4）。语音服务与媒体不可同时出声。
  - 内存：解码缓冲走 PSRAM。
- **依赖**：SD 卡已有；新增解码组件；无新硬件。
- **工作量 M–L**；**优先级 P1**。
- **验收**：从桌面进 MP3 → 选 SD 上的歌播放出声、可暂停/切歌/调音量；切去其它 App 声音停、回来可续播。

### App-3 照相机

- **UX**：全屏取景（实时预览）→ 快门拍一张 → 自动存 `/sdcard/DCIM` 并出缩略回看；可切前后设置（镜像/翻转）；(可选)长按录像（H.264 硬编到 SD）。
- **技术路径**：复用 A 方向——`esp_video` CSI 取帧，**PPA** 缩放/旋转到 1280 画布实时预览（A1）；快门即把帧走硬件 JPEG 编码存盘（现有 `image_to_jpeg` / esp_video 路径）；相片管理交给"文件管理 App"。
- **前置硬件 ①**：板上必须有 **MIPI-CSI 摄像头**（或退而求其次用 **USB UVC 摄像头**作输入，依赖里已有 `usb_host_uvc`）。
- **工作量 M–L（预览是难点）**；**优先级 P2（等硬件确认后优先）**。
- **验收**：取景流畅（目标 ≥15fps）、拍照即存 SD、文件管理里能看到并打开照片。

### App-4 文件管理

- **UX**：浏览 `/sdcard`（及 `/usb`）目录树：图标分类型、路径栏/面包屑、列表与网格切换；点文件按类型处理：**音乐→唤起 MP3 播放**、**图片→看图预览**、**音频→试听**；长按/多选：删除、重命名(v1 可只读+删除)、详情（大小/日期）、复制到其它目录（可选）。
- **技术路径**：纯 UI + `esp_vfs_fat`（已挂载）；图片预览复用现有 `jpg/png` 解码与 `esp_new_jpeg`；文件→App 的唤起定义一种**轻量 intent（open(path, mime)**，供 MP3/看图/相机回看共用。
- **依赖**：无新硬件；等 D-H2a（U 盘）后自动多一个卷。
- **工作量 M**；**优先级 P1**（它给 MP3、相机打地基，建议在相机/MP3 之前或并行做）。
- **验收**：能在 SD 上浏览/删除/看图；点 mp3 能唤起播放器定位到该文件。

### App-5 USB 连电脑当"副屏"

- **先说清约束（重要）**：普通"显示器"是 OS 原生设备，ESP 上做不到即插即用 —— 没有 DisplayLink 类硬件解码、没有 OS 驱动会把它当显卡。**可行形态 = PC 端一个配套小程序**采集屏幕/窗口 → 压缩推流 → 设备解码显示。
- **推荐传输**：**USB**。用 **ECM/RNDIS 网卡 gadget**（设备模式，`esp_tinyusb`）把 USB 变成虚拟网卡，480Mbps 下带宽充足；PC 程序经此网卡把画面推到设备（若 USB gadget 调不通，退 WiFi——但本需求指定 USB）。
- **设备侧**：新 App 收流（`esp_netif` + TCP）→ **MJPEG 解码（`esp_new_jpeg`，软件，P4 向量优化）** → **PPA 缩放**到目标窗口上屏。注意 **P4 只有 H.264/MJPEG 硬编码器、无硬解码**，软解 MJPEG 是最现实方案。
- **体验预期（要如实告诉用户）**：非低延迟游戏屏，目标是 **"信息/工具副屏"**：PC 端程序把窗口缩到 ≤ VGA 级推 **10–20fps**，设备端显示延迟 150–300ms，适合看监控、歌词、状态面板、网页摘要。两条路线：
  - 5a **镜像副屏**：整屏/窗口镜像（带宽与 CPU 压力最大）。
  - 5b **工具副屏**（更推荐起步）：PC 端小程序主动推送**结构化/静态卡片**（日历、天气、待办、播放器、系统监控），设备侧渲染 —— 压力小、体验稳。
- **前置硬件**：USB 口需是 **Device/OTG** 能力（D 方向待确认项）；依赖 USB gadget 组件 + PC 端小程序开发（这是**另一个小软件项目**，需 Windows/macOS 端）。
- **工作量 L+（含 PC 端）**；**优先级 P3（研究性）**。
- **验收（研究目标）**：PC 小程序把一个窗口以 MJPEG 推到设备全屏显示并稳定运行 10+fps；或 5b 的卡片式副屏稳定显示。

## 5. 既有方向（A–D）如何归位

| 旧方向 | 在本"平板"中的新位置 |
|---|---|
| B1 待机 Home / B2 动效 / B3 页面 | 吸收进 **Launcher/壳**（桌面时钟 widget、图标桌面、返回手势） |
| A0/A1/A2 摄像头视觉 | **App-3 相机**；A0"拍照识物"进 **App-1 助手**的视觉功能（等硬件）；A2 录像=相机 App 的可选录像 |
| D-H1 USB 键盘 | 全局**输入服务**（见 2.6） |
| D-H2a U 盘导出/导入 | 并入 **App-4 文件管理**（第二卷 `/usb`），也是相机/录像的离线导出通道 |
| D-D2 UAC 免驱音箱/麦克风 | 独立小功能，暂挂 USB 方向，不做进副屏 |
| D4 ECM/RNDIS gadget | **App-5 副屏**的传输底座（USB 虚拟网卡） |
| D-H3 手机/4G USB 共享网络 | 保留为 USB 方向的次选能力 |
| C1 BLE POC / C2 外设 | 保持原优先级，作为系统能力的锦上添花 |

## 6. 增量路线图（以"平板壳"为主线）

| 阶段 | 内容 | 依赖 | 出口标准 |
|---|---|---|---|
| **Phase 0 壳** | AppManager + Launcher + 状态栏上移 layer_top + 助手 App 化（D2 改造） | 无新硬件 | 开机进桌面；图标进出助手；退出停麦 |
| **Phase 1** | **App-4 文件管理**（含看图、delete；顺带跑通 intent 骨架） | 无新硬件 | 可浏览/看图/删除 |
| **Phase 2** | **App-2 MP3**（+Helix 解码 +AudioFocus） | 无新硬件 | 本地歌单播放/切歌/续播 |
| **Phase 3** | USB 存储进文件管理（D-H2a）+ USB 键盘（D-H1，可选） | ① USB 口为 Host/OTG | U 盘在文件管理里可读可拷 |
| **Phase 4** | **App-3 相机**（取景+拍照存 DCIM；A0 视觉对话入助手） | ① CSI 摄像头（或 UVC） | 取景/拍照/回看可用 |
| **Phase 5 研究** | **App-5 USB 副屏** POC（USB gadget→MJPEG）；BLE POC 等 | ① USB 为 Device/OTG + PC 端程序 | 5a/5b 任一跑通 |

> Phase 0–2 全部**无需新硬件**、彼此独立，可先行；Phase 3/4 卡在两个硬件确认（USB 形态、CSI 座）；Phase 5 是独立研究项目。

## 9. 风险与注意事项

- **重构风险**：把现有全局语音状态机改造成"助手 App 内运行"是最容易回归的改动（网络/OTA/时间保持系统级，别误伤）。先做壳子（Phase 0）验证再展开。
- **音频互斥**：单 ES8389，语音(16k opus) ↔ 媒体(44.1k mp3) 的采样率切换与释放必须收敛到 AudioFocus，否则花屏级故障（无声/爆音）。
- **LVGL 线程模型**：所有 LVGL 调用走 `DisplayLockGuard`/`Lock`；App 切屏注意在适配器锁内完成。
- **内存**：每 App 独立 screen 随开随建/随关随毁，控制常驻；解码/取景缓冲算 PSRAM 账。
- **副屏预期管理**：不是低延迟游戏副屏；先把"工具副屏"做稳再做镜像。
- **保持 fork 可合并性**：壳与 App 先收敛在 `main/boards/p4c5/`，共享层改动（若有）做向后兼容。
